# Проверка Android-приложения, 28 октября 2026

Проверены расчёт порций и нутриентов, дневные суммы, блюда из ингредиентов, статистика белка, журнал веса, чтение базы, резервное копирование и ссылки на установщики. Это проверка кода и данных; новый прогон UI на устройстве в неё не входит.

## Исправления

- При неполных данных за день доля калорий из белка больше не выдаётся за точное число. Белок на кг веса помечается как нижняя граница. День с неизвестным белком и известной суммой ниже цели исключается из подсчёта успехов/неудач; если известной суммы уже достаточно для цели, успех учитывается.
- Удаление последнего взвешивания возвращает текущий вес профиля к предыдущему взвешиванию, а при пустом журнале — к начальному весу. Вес, вручную изменённый в профиле после взвешивания, сохраняется. Ранее удалённое значение могло участвовать в дальнейших оценках расхода калорий.
- Чтение базы группирует строки по типу одним проходом вместо отдельных проходов по всему журналу для каждого типа. JSON каждой записи по-прежнему разбирается: для очень больших журналов дальнейшим улучшением будет раздельное наблюдение за таблицами/типами, особенно при обновлении шагов. Ускорение на устройстве не измерялось.
- Удалены функции без вызовов `plural`, `kindLabel`, `HealthRepository.observeDay`, `HealthRepository.observeWeek`. Обработчики Android и WebView сохранены: их вызывает платформа.
- README направляет новую установку и обновление к последнему выпуску. Архивная база v6 остаётся доступной. Файлы `HealthChecker-update-vN.apk` содержат полное приложение, а не разницу между версиями.

## Питание и каталог

В поставляемом каталоге 7 834 уникальных продукта: 7 793 записи USDA и 41 локальное блюдо/вариант. Все значения USDA на 100 г сверены с локальным исходным `usda-slim.json`: расхождений по калориям, белкам, жирам, углеводам и клетчатке нет. Единственное предусмотренное заполнение — нулевая клетчатка при нулевых углеводах. Отсутствующие значения в остальных случаях остаются неизвестными.

Для всех продуктов проверены конечные неотрицательные значения: калории до 1 000 ккал/100 г, каждый нутриент до 100 г/100 г; положительный вес порций и плотность. Проверки закреплены в `tools/catalog/test_catalog_integrity.py`. Сверка с исходным USDA пропускается, если игнорируемый исходник не скачан; проверка поставляемого каталога работает всегда.

Математика порций: граммы × значение на 100 г / 100; штуки × редактируемый вес штуки; миллилитры × плотность, затем тот же расчёт по массе. У блюда суммируются ингредиенты и делятся на фактический вес готового блюда; изменение массы при приготовлении меняет концентрацию, сохраняя сумму нутриентов ингредиентов. Неизвестный нутриент ингредиента делает этот нутриент блюда неизвестным.

41 локальная позиция содержит оценки, в том числе ресторанные блюда и суши. Их нельзя считать лабораторно подтверждёнными значениями для конкретного ресторана или упаковки. Формула 4/4/9 не используется для принудительной перезаписи калорий USDA: исходные значения могут использовать специальные энергетические коэффициенты. Переводы названий не проходили полную повторную ручную экспертизу.

## Оставшиеся риски

- `HealthRepository.replaceSnapshot` фиксирует базу до замены файлов картинок упражнений. Ошибка файловой системы на втором этапе может оставить восстановленную базу со старыми или частично заменёнными картинками. Это найденный по коду риск; отказ диска не воспроизводился. Для устранения нужен отдельный этап подготовки файлов и согласованный откат базы/файлов. Обычные успешные восстановления покрыты существующими тестами, сценарий ошибки файловой системы — нет.
- Датчик шагов меняет строку в общей таблице, из-за чего Flow повторно разбирает JSON всего журнала. Группировка уменьшает число проходов, но не устраняет это повторное декодирование. Отдельное наблюдение за шагами стоит делать при подтверждённой задержке на большом журнале.
