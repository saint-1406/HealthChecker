# Обновление из приложения

Раздел **Профиль → О приложении → Обновления** проверяет выпуски GitHub `saint-1406/HealthChecker`, скачивает полный подписанный APK последней версии, проверяет его и передаёт системному установщику Android. Новая версия ставится поверх текущей: дневник, находки, прогулки и настройки сохраняются. Поток и формулировки повторяют обновление ATLAS (`Updater.java` и `update.js` проекта ATLASTaker).

## Как это выглядит

1. «Проверить обновления». Приложение запрашивает `https://api.github.com/repos/saint-1406/HealthChecker/releases/latest`.
   - Версия не новее установленной: «Установлена последняя версия (1.16.5)».
   - Новее: «Доступна версия 1.16.6 · 182,1 МБ», «Что нового» (текст выпуска) и кнопка «Обновить». Для больших файлов есть подсказка скачивать по Wi‑Fi.
2. «Обновить»: прогресс «Загружаю обновление… N%», загрузку можно отменить.
3. Проверка файла. При любой ошибке файл удаляется до установщика: «Скачанный файл не прошёл проверку (…) и удалён. Ничего не установлено — попробуйте ещё раз».
4. Если Android ещё не разрешил приложению устанавливать APK, открываются настройки «Установка неизвестных приложений» для HealthChecker: «Разрешите HealthChecker устанавливать приложения (Android спросит один раз) и вернитесь — установка продолжится сама». После возврата установка запускается один раз автоматически. Если разрешение не выдано, повторно настройки не открываются: «Обновить» можно нажать позже.
5. «Файл версии 1.16.6 проверен — открываю установку». Дальше решает системный установщик. Если установку отменить, кнопка снова доступна. Скачанный файл остаётся в кеше до установки новой версии, поэтому повторная загрузка не нужна.

**Тихая проверка при запуске.** Переключатель «Проверять раз в день при запуске» включён по умолчанию. Не чаще раза в сутки, через 15 секунд после открытия дневника, приложение без сообщений проверяет GitHub. Если есть новая версия, над главными экранами появляется строка «Доступна версия X — открыть». Нажатие открывает «Профиль → О приложении» с разделом обновлений, крестик скрывает строку для этой версии. Ошибки тихой проверки не показываются. Если переключатель выключен, приложение выходит в сеть только по кнопке.

## Проверки файла

Ожидается выпуск с тегом `v<versionName>` и двумя файлами: `HealthChecker-update-v<versionName>.apk` и `HealthChecker-update-v<versionName>.apk.sha256`. Их создаёт `scripts/build-apk.ps1 -Publish`.

1. Опубликованная SHA-256 берётся из файла `.sha256` (формат `HASH  имя`; BOM, CRLF и регистр не мешают; имя в файле должно совпадать с APK). Если GitHub сообщает собственный `digest` файла, обе суммы должны совпасть. Иначе загрузка не начинается.
2. Перед загрузкой проверяется свободное место: размер файла плюс 32 МБ запаса.
3. APK пишется в `cache/updates/<имя>.part` с подсчётом SHA-256. Размер должен точно совпасть с размером из GitHub, хеш — с опубликованным.
4. Через `PackageManager.getPackageArchiveInfo` проверяется, что это `az.healthchecker.app`, `versionCode` выше установленного и есть хотя бы один общий сертификат подписи с установленной версией (с учётом ротации ключа). Если телефон не может прочитать подпись из файла, её проверяет системный установщик: Android не установит обновление с другим ключом.
5. Только после этого `.part` переименовывается в `.apk` и передаётся установщику через `UpdateFileProvider` (authority `az.healthchecker.app.updates`, доступен только каталог `cache/updates/`) с `ACTION_VIEW` и временным правом чтения.

Устаревшие файлы (`.part` и APK версий не новее установленной) удаляются при следующем запуске.

## Сеть и разрешения

Обновлению нужны `INTERNET` и `REQUEST_INSTALL_PACKAGES`. Других сетевых функций нет: каталог, сканер, карта, дневник и видео работают без сети.

- Сеть используется только в `az.healthchecker.update.GithubHttp`: при нажатии «Проверить обновления» или «Обновить» и при ежедневной проверке, если она включена.
- Разрешены только HTTPS на `api.github.com`, `github.com`, `objects.githubusercontent.com` и `release-assets.githubusercontent.com`. Редиректы обрабатываются вручную, и каждый адрес проверяется по этому списку. Переход на другой хост или HTTP прерывает запрос, как и более 5 редиректов.
- Запросы анонимны: передаются только `User-Agent: HealthChecker-Android-Updater` и заголовки GitHub API. Данные дневника не отправляются.
- `scripts/build-apk.ps1` проверяет все разрешения APK по белому списку. Любое новое разрешение, включая `ACCESS_BACKGROUND_LOCATION`, останавливает сборку.

## Сообщения об ошибках

| Ситуация | Текст (RU) |
|---|---|
| Нет сети или DNS | Нет подключения к интернету. Проверьте сеть и попробуйте ещё раз. |
| Лимит GitHub API (403/429) | GitHub временно ограничил число проверок. Попробуйте через час. |
| Нет выпуска или нужных файлов | На GitHub не найден выпуск с файлом обновления. |
| Другая ошибка GitHub | Не удалось проверить обновления: GitHub ответил ошибкой (…). |
| Мало места | Не хватает места для обновления: освободите ещё около N МБ… |
| Обрыв загрузки | Загрузка прервалась (…). Ничего не установлено, данные не тронуты — попробуйте ещё раз. |
| SHA-256, размер, пакет, версия, ключ | Скачанный файл не прошёл проверку (…) и удалён. Ничего не установлено — попробуйте ещё раз. |
| Установщик не открылся | Не удалось открыть установку: … |

Все тексты есть на английском (`UpdateTexts`).

## Код и тесты

- `update/UpdateRules.kt`: разбор ответа GitHub и `.sha256`, сравнение версий, белый список адресов.
- `update/UpdateHttp.kt`: HTTPS-клиент с проверкой каждого редиректа.
- `update/UpdateEngine.kt`: проверка выпуска, загрузка и все проверки файла, без UI.
- `update/UpdateInstaller.kt`: FileProvider, интенты установщика и настроек, чтение подписи через PackageManager.
- `update/UpdateViewModel.kt`, `ui/update/UpdateViews.kt`: раздел профиля, строка-уведомление и возврат из настроек.
- Тесты (`app/src/test/java/az/healthchecker/update/`): разбор выпуска и контрольных сумм, отказ от чужих хостов и HTTP-редиректов, коды ответа, удаление файла при несовпадении SHA-256, размера, пакета, версии или ключа, нехватка места, отмена, очистка кеша, URI FileProvider, разрешения манифеста.

Ручная проверка на устройстве: установить сборку N, опубликовать N+1 (или подставить тестовый выпуск), нажать «Проверить обновления» → «Обновить», выдать разрешение и убедиться, что после установки дневник на месте, а в профиле показана новая версия.
