# Сканер товаров

Пользователь одобрил добавление предложенного сценария: камера → штрихкод → локальный товар → явный онлайн-поиск при отсутствии → подтверждение/исправление → сохранение на телефоне. Разрешение камеры запрашивается при запуске сканирования. Отказ и отмена оставляют ручной ввод кода доступным. Распознавание таблицы питания и блюда по фото в этот выпуск не входят.

Выбор реализации: ZXing Android Embedded со встроенным декодером, без Google Play Services; альтернативная модель ML Kit добавляет зависимость/размер, внешний сканер требует ещё одно приложение. Код товара EAN-8/EAN-13/UPC-A/GTIN-14 проверяется по контрольной цифре; UPC-A и EAN-13 с ведущим нулём должны находить один товар. UPC-E из камеры разворачивается в UPC-A. QR/URL не исполняются.

Карточка Food получает необязательный barcode, сохраняемый в существующей Room-записи и резервной копии схемы 8 (чтение 1–8). Локальный поиск по нормализованному коду; один код не может принадлежать двум карточкам. Данные Open Food Facts импортируются только после подтверждения, с указанием источника/лицензии; существующий каталог USDA не изменяется. Удаление/изменение карточки не переписывает историю питания.

Сеть: только фиксированный HTTPS-хост Open Food Facts, только код товара, без дневника/фото/профиля. Тайм-ауты, ограниченный ответ, понятные состояния «не найдено» / «нет связи» / «неполные данные», повтор вручную. Не считать неизвестные нутриенты нулевыми; не брать рассчитанные OFF estimated nutrients вместо данных этикетки. Значения кДж пересчитывать в ккал только при отсутствии ккал. Порционные значения не принимать за значения на 100 г.

Перед сохранением пользователь проверяет основу (100 г/100 мл), название, БЖУ, вес упаковки. Для 100 мл необходим явный вес 100 мл для перевода в нынешнюю внутреннюю модель per100g; плотность не подставляется автоматически. Тогда доступны и граммы, и миллилитры. Неизвестные/некорректные поля требуют исправления, онлайн-ответ не сохраняется автоматически.

Доступ: кнопка штрихкода на поиске еды (включая выбор ингредиента), ручной ввод кода, повторное сканирование; готовый локальный товар открывает существующую форму порции. Сохранённая новая карточка открывает ту же форму. Еда, корзина и дата используют существующие пути, без скрытой записи. RU/EN, Android 8+, короткий экран/шрифт 200%, цели касания 48 dp.

Локальный подписанный полный APK v15 с тем же appId и ключом. Автоматическая публикация GitHub в этот запрос не входит; предыдущая публикация относилась к v14. Проверки: парсер/единицы/проверочная цифра, конфликты локальных кодов/копии, UI ручного ввода и повторного поиска без сети, работа декодера на изображении, старые сценарии и обновление v14→v15. Физическая камера — только если подключён телефон; ограничения испытаний указать честно.
