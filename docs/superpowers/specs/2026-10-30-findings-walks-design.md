# 1.16.2: находки, места и прогулки без сети

## Согласованный запрос
Пользователь хочет галерею интересных товаров, включая непищевые: штрихкод, фото, данные/заметка и место покупки. Карта должна показывать магазины, интересные места и историю передвижений локально. Ответы пользователя: запись **по кнопке «Начать прогулку»**, продолжается с выключенным экраном; первая версия показывает **историю путей и места без записанных посещений**, без автоматического построения маршрута10км. Новый формат видимой версии1.16.2, code18 (прошлый опубликованный16.1/code17 не меняется).

## Пользовательский сценарий
Пятая вкладка «Находки» перед «Профиль»: внутри «Каталог», «Карта», «Прогулки». Существующие идентификаторы вкладок сохраняются (Профиль=3, Находки=4). Каталог — фото-карточки, поиск, категории Еда/Уход/Другое, избранное. Добавление камерой/галереей/вручную; для штрихкода используются личные находки и встроенный пищевой OFF-каталог. Вне пищевой базы можно сохранить любой товар вручную без калорий. Непищевые вещи не попадают в Food/дневник питания.

Находка: название, категория, необязательные штрихкод/бренд/заметка/фото, избранное, список мест покупки с текстом цены/комментария. Место: название, тип Магазин/Интересное/Другое, координаты, заметка. Поставить точку можно долгим нажатием на карте или по своей позиции; GPS не нужен для ручных точек. Одна находка может иметь несколько мест покупки. Карточка места показывает связанные находки.

Встроенная карта всего Азербайджана: Mapsforge0.25.0, официальный файл карты от26.09.2026 около56МБ, OSM/ODbL. Стиль и изображения локальные, разрешения INTERNET нет. Подготовка карты — worker с проверкой размера/SHA и атомарной активацией. Отображаются метки, текущая позиция, выбранный/активный трек и слой записанных посещений. «Нет записей о посещении» не равно «человек никогда здесь не был». Вне покрытия фон отсутствует, пользовательские координаты остаются валидными.

Начать/пауза/продолжить/завершить. История: дата, время, длительность без пауз, расстояние, просмотр трека, удаление завершённой прогулки. GPS_PROVIDER, точная геолокация и пользовательская foreground-location служба с постоянным уведомлением и действиями паузы/остановки. Нет скрытого постоянного трекинга, автоматического старта по перезагрузке или ACCESS_BACKGROUND_LOCATION. GPS-потеря/некачественные координаты/прыжки не соединяются ложной прямой. Пауза разрывает сегмент; приложение не рисует посещение между несмежными измерениями. Если сервис прерван, данные сохраняются, продолжение только по решению пользователя. Калории тренировки автоматически не добавляются (во избежание двойного учёта шагов).

## Хранение и восстановление
HealthDatabase v2: отдельная таблица explore_records с метаданными находок/мест/прогулок, без GPS-точек и JPEG внутри наблюдаемого состояния. Миграция1→2 сохраняет старые таблицы. HealthDatabase.open(context,name) включает multi-instance invalidation: служба и UI видят изменения. Existing core-record observers не перечитывают весь дневник на каждый GPS-fix.

Фото — неизменяемые private JPEG файлы с UUID-именами; GPS — private append-only binary-файл (32байта: latDouble,lonDouble,timeLong,accuracyFloat,flagsInt). В метаданных число записанных точек и lastPoint. Файл сначала синхронизируется, затем checkpoint Room; лишний хвост после сбоя не считается committed. Фото грузятся только для видимых карточек, маршруты/посещения обрабатываются потоково; многомиллионная база OFF не дублируется.

Резервная копия — ZIP с snapshot.json (старый UserSnapshot плюс optional ExploreSnapshot), файлами новых фото/треков и манифестом SHA-256/размеров. Потоковая запись/чтение без единого ByteArray всей галереи. Старые JSON1–9 продолжают читаться; schema10 вводит explore. Перед восстановлением все пути/UUID/хеши/размеры/ссылки проверяются в staging. Замена core и explore-метаданных в одной Room-транзакции; media replacement имеет журнал восстановления, как уже существующий ImageReplacement. Перед restore запись прогулки останавливается и IO завершается. Старые исправные копии сохраняются при любой ошибке. Точки сохраняются локально по ходу; backup revision обновляется на паузе/завершении, ручная копия может взять текущий checkpoint. Встроенные OFF и карта в копию пользователя не входят.

## Осознанные решения
Технические детали заполнены самостоятельно в рамках исходного поручения пользователя; функциональные развилки подтверждены двумя ответами выше. Область карты — весь Азербайджан, подход подходит текущему региону Баку; онлайн-карты/внешние аккаунты/автопрокладка/общий каталог косметики не добавляются. Опубликованные файлы16.1 неизменны. Здесь готовим исходники и подписанный APK1.16.2; внешний выпуск — при просьбе залить в GitHub.
